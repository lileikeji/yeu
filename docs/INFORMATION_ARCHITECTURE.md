# 仰恩大学新生入学指南系统信息架构

> 文档版本：0.1
> 适用范围：MVP 前台、单人维护后台、PWA 与微信内访问
> 关联文档：[PRD.md](./PRD.md)、[MAP_INTERACTION_SPEC.md](./MAP_INTERACTION_SPEC.md)

## 1. 架构目标

信息架构围绕新生的即时问题组织，而不是照搬学校行政组织结构。用户首先看到“我要去哪里、我要办什么、现在需要注意什么”，再按需查看部门、社团和校园背景。

设计目标：

- 任何核心地点最多通过首页一次点击进入地图，再通过一次点击打开详情。
- 任何流程步骤都能直接关联地点、部门和来源，避免用户记住名称后重新搜索。
- 本科与专升本共用大部分结构，在有差异的步骤和指南上显式标注受众。
- 公开端无需登录；本地清单或最近访问不成为内容可达性的前提。
- 地图脚本加载失败或定位被拒绝时仍有在线文本列表和详情；设备断网时进入专用说明页，不展示未经版本校验的旧正文。
- 后台按内容实体组织，适合一名维护者快速发现待更新项目。

## 2. 内容域与层级

### 2.1 一级内容域

| 内容域 | 回答的问题 | 核心实体 |
| --- | --- | --- |
| 地图 | 在哪里、怎么到、附近有什么 | 地点、地点分类、校区/区域、商铺 |
| 报到 | 先做什么、带什么、去哪里 | 流程、步骤、材料、适用人群 |
| 指南 | 校园卡、网络、快递等怎么处理 | 指南、主题、常见问题 |
| 校园 | 学校、部门和常用服务是什么 | 校园介绍、部门、服务事项 |
| 社团 | 有哪些社团、何时招新、如何联系 | 社团、类别、招新状态 |
| 周边 | 校外有哪些新生常用服务 | 商铺/服务地点、类别 |
| 搜索 | 某个名称或问题对应什么内容 | 跨实体搜索结果 |
| 反馈与说明 | 信息错了怎么办、资料从哪里来 | 纠错、来源、隐私与非官方声明 |

### 2.2 内容关系

信息关系应是双向可达的：

```text
报到流程/指南 ----关联----> 地点 <----归属/关联---- 部门
      |                       |
      |                       +----类别/区域----> 地图筛选
      |
      +----引用----> 来源

社团 ----活动/招新地点----> 地点
商铺 --------------------> 周边地点
所有公开实体 ------------> 纠错反馈
```

关键规则：

- 地点是地图中的统一实体，校内设施与周边商铺通过 `scope` 或类型区分，不创建两套不兼容坐标模型。
- 流程是有序步骤集合，指南是可独立阅读的主题内容；两者可以互链，但不混为同一内容类型。
- 部门详情描述职责和服务渠道，具体怎么办应链接流程或指南。
- 来源作为独立记录复用，前台只展示对用户有帮助的标题、平台、链接、官方属性和访问日期。
- 发布状态至少包含草稿、已发布和已归档；公开端只检索已发布且未失效的内容。

## 3. 前台全局导航

### 3.1 移动端主导航

移动端采用固定底部导航，保持四个主入口，避免图标和文字拥挤：

| 入口 | 路由 | 内容 |
| --- | --- | --- |
| 首页 | `/` | 当前重点、快捷任务、公告和精选内容 |
| 地图 | `/map` | 校内/周边地图、筛选、搜索和地点详情 |
| 办事 | `/procedures` | 报到流程及高频事项 |
| 更多 | `/discover` | 指南、校园、部门、社团、周边、来源与关于 |

搜索按钮作为首页、地图和详情页的全局操作，不占第五个底部导航项。详情页返回应回到发起页面并保留地图或列表状态。

### 3.2 桌面端导航

桌面端顶栏提供：首页、地图、报到与办事、指南、校园、社团、周边；右侧提供搜索。低频的来源、反馈、关于和隐私置于页脚或“更多”菜单。

### 3.3 首页信息顺序

首页不是宣传型落地页，首屏直接服务新生任务：

1. 全局搜索框。
2. “打开校园地图”主要入口。
3. 报到、找宿舍/教学楼、校园卡与网络、快递外卖、周边商铺、社团招新六个快捷入口。
4. 当前有效公告或临时变更；无公告时不保留空区域。
5. 报到进度/关键步骤入口（若启用本地清单）。
6. 精选地点与指南。
7. 最近核验时间、来源说明和纠错入口。

### 4.2 地图 URL 状态

地图的可分享状态使用查询参数表达，避免只存于运行时内存：

| 参数 | 示例 | 作用 |
| --- | --- | --- |
| `place` | `/map?place=library` | 打开并高亮指定地点 |
| `q` | `/map?q=快递` | 带入关键词并显示结果 |
| `category` | `/map?category=dormitory` | 应用单个类别筛选 |
| `scope` | `/map?scope=campus` | 限定校内或周边 |
| `from` | `/map?place=library&from=report` | 可选来源上下文，用于返回原流程 |

多个筛选值如确有需要使用重复参数或逗号分隔，但在开发前统一一种解析约定。地图中心点和缩放级别无需默认写入 URL；只有用户主动分享当前视图时再加入，避免链接过长。

### 4.3 搜索结果结构

`/search?q=` 使用普通关键词检索，不包含 AI 回答。结果顺序遵循：

1. 名称精确匹配和别名匹配。
2. 当前有效的报到流程与官方高频指南。
3. 地点及部门。
4. 社团和周边商铺。
5. 正文相关结果。

结果卡片必须显示内容类型和关键上下文，例如地点显示区域、流程显示适用人群、社团显示招新状态。推广状态未来不得改变默认相关性排序，推广内容应另设显著标识区域。

建议别名和关键词示例：

- Wi-Fi、校园网、网络。
- 饭卡、一卡通、校园卡。
- 菜鸟、驿站、快递点、取件。
- 宿舍号、楼栋正式名、学生常用简称。
- 教务处、办成绩/学籍等用途词。

## 5. 页面信息结构

### 5.1 地图页 `/map`

地图页由地点结果、地图画布和地点摘要组成，三者共享搜索、筛选和选中状态。

桌面可用宽度不低于 1024px 时：

1. 左侧约 280px 地点列表，包含搜索/筛选摘要、结果数和持续可见的当前项高亮。
2. 右侧地图占据剩余空间，展示按 zoom 分级的图钉、名称标签与数字聚合点。
3. 点击列表项后地图平移并选中对应图钉；点击图钉后列表滚动到对应项。
4. 选中地点在图钉附近打开白色详情浮层，列表不关闭；浮层越界时自动换边或调整地图安全区域。

移动端从上至下/从底层至浮层：

1. 地图画布，占据可用主区域。
2. 顶部搜索框，返回键只在存在上游上下文时出现。
3. 横向类别筛选和校内/周边切换。
4. 定位、恢复校园视图和图层/列表切换控件。
5. 按缩放级别显示的标点、名称与数字聚合点。
6. 三档底部抽屉承载地点列表或选中地点摘要；上拉显示更多，点击进入独立详情。
7. 网络、定位或数据异常的非遮挡提示。

“附近”不得在未取得定位或未说明距离基准时给出虚假距离。地图图标不能只靠颜色传达类别，选中态需同时使用尺寸、白色双描边/外环、层级和标签。常态图钉为 32px、选中态为 44px，触控命中区至少 44px；聚合点按 36/44/52px 三档表达数量。

已验证的第三方地图工作台只作为列表/地图联动的交互参考。本项目使用自有颜色、Lucide 图标、标签碰撞隐藏和低 zoom 数字聚合，不复制其专有图标、品牌色、卡片排版或工作台操作。完整行为见 [MAP_INTERACTION_SPEC.md](./MAP_INTERACTION_SPEC.md)。

### 5.2 地点详情 `/places/:slug`

信息顺序：

1. 名称、别名、类别、校内/周边标签和核验状态。
2. 主图或真实现场图（如有），不可用装饰图代替地点证据。
3. “地图查看”“外部导航”主要操作。
4. 详细位置：校区/区域、楼栋、楼层/房间、地址。
5. 开放时间、电话、服务范围等结构化信息。
6. 到达提示、入口特征、注意事项。
7. 关联流程、指南、部门或社团。
8. 来源、最后核验日期和纠错入口。

已停用、搬迁或待核实状态必须在首屏出现，不得只放在正文末尾。

### 5.3 流程详情 `/procedures/:slug`

信息顺序：

1. 标题、适用人群、办理方式、预计耗时和当前有效期。
2. 重要变更/待通知状态。
3. 所需材料总览。
4. 有序步骤：动作、说明、时间、地点、负责部门。
5. 常见问题与失败处理。
6. 关联指南、来源、核验日期和纠错入口。

步骤内的地点名称直接链接 `/map?place=...&from=...`；返回流程时恢复原步骤位置。

### 5.4 指南详情 `/guides/:slug`

信息顺序：标题和摘要、适用人群、更新时间、关键结论、分节正文、关联地点/部门、来源、纠错。长文提供页内目录，但不得用目录代替搜索友好的小标题。

### 5.5 部门详情 `/departments/:slug`

信息顺序：名称/简称、面向新生的职责、可办理事项、办公地点、服务时间、公开联系方式、相关流程/指南、来源和核验日期。组织沿革等背景信息后置。

### 5.6 社团详情 `/clubs/:slug`

信息顺序：名称、类别和招新状态、简介、活动方向、招新时间/方式、活动地点、经同意公开的组织联系方式、最后核验日期。招新结束后保留社团基础介绍，但将本期报名入口置为失效状态。

### 5.7 周边列表 `/nearby`

支持列表/地图切换，首版筛选项包含餐饮、住宿、零售、医疗、打印/维修、交通等实际收录类别。卡片显示名称、类别、所在区域、营业状态（仅在数据可靠时）和核验时间；不显示未经验证的评分、销量或“最佳”等宣传性结论。

## 6. 核心用户流程

### 6.1 找宿舍或教学楼

```text
首页快捷入口/全局搜索
  -> 地图带关键词或类别打开
  -> 从地点列表或标点选择目标，另一侧同步高亮
  -> 查看位置摘要与到达提示
  -> 查看完整详情或打开外部导航
  -> 到达失败时查看文字路线/提交纠错
```

保留搜索词、筛选条件和地图视图，用户从详情返回时不重新开始。

### 6.2 完成报到

```text
首页“报到流程”
  -> 选择本科/专升本（仅在存在差异时）
  -> 查看材料与步骤
  -> 点击当前步骤地点
  -> 地图高亮报到点
  -> 返回原步骤继续
  -> 可选：本机勾选完成
```

若当年通知尚未发布，流程页以准备性信息为主，明显显示“等待学校当年通知”和官方入口。

### 6.3 校园卡与网络

```text
首页快捷入口/搜索
  -> 对应指南
  -> 根据场景选择“首次办理/故障/补办”等章节
  -> 按步骤操作
  -> 需要线下处理时打开服务地点或部门
```

### 6.4 快递与外卖

```text
首页快捷入口
  -> 快递/外卖主题页或地图筛选
  -> 选择站点/取餐点
  -> 核对服务范围、时间和临时通知
  -> 地图查看或文字路线
```

### 6.5 社团招新

```text
首页“社团招新”/更多“社团”
  -> 按兴趣分类或招新状态筛选
  -> 社团详情
  -> 查看招新时间、地点和公开联系方式
  -> 地点跳转地图或访问经审核的外部报名入口
```

### 6.6 纠错反馈

```text
任一详情页“信息有误”
  -> 自动关联页面和内容 ID
  -> 选择问题类型并填写说明
  -> 可选填写联系方式
  -> 提交成功
  -> 管理员后台待处理
  -> 核验、更新内容并关闭反馈
```

### 6.7 PWA 与微信访问

PWA：浏览器访问 -> 满足安装条件 -> 用户主动安装 -> 从主屏进入 -> 在线读取最新内容；断网导航进入说明页。安装提示不得阻断首次任务，V1 不承诺离线正文。

微信：收到深链接 -> 微信内直接打开详情 -> 使用核心内容 -> 导航能力不可用时复制地址或提示用系统浏览器打开。不得强制用户关注、登录或安装才能看正文。

## 7. 状态与降级设计

| 状态 | 用户可见行为 | 主要操作 |
| --- | --- | --- |
| 首次加载 | 显示稳定骨架，不移动主要控件 | 等待、返回 |
| 空结果 | 说明筛选或关键词没有结果 | 清除筛选、浏览分类、反馈缺失地点 |
| 请求失败 | 保留已加载内容，说明请求失败 | 重试、返回首页 |
| 地图失败 | 展示地点文本列表与详情入口 | 重试地图、复制地址 |
| 定位拒绝 | 不重复强制请求 | 手动搜索、恢复校园视图、查看授权说明 |
| 离线 | 进入断网说明页，不显示旧正文 | 重新连接后重试、返回首页 |
| 内容过期 | 显示过期/待复核，不提供过期行动按钮 | 查看来源、官方入口、反馈 |
| 内容下架 | 返回 404/410 语义页面 | 搜索相似内容、回到对应分类 |
| 外链受限 | 说明微信或系统限制 | 复制地址/链接、在浏览器打开 |

## 8. 后台信息架构

### 8.1 后台导航与路由

后台 MVP 仅服务单管理员，不展示无实际能力的角色管理入口。

| 路由 | 模块 | 主要能力 |
| --- | --- | --- |
| `/admin/login` | 登录 | 管理员认证、错误与限流提示 |
| `/admin` | 工作台 | 待处理反馈、待复核/将过期内容、近期修改、快捷新建 |
| `/admin/places` | 地点 | 搜索、筛选、新建、批量状态查看 |
| `/admin/places/new` | 新建地点 | 字段录入、地图选点、坐标系、关联和来源 |
| `/admin/places/:id` | 编辑地点 | 预览、发布、更新、归档 |
| `/admin/procedures` | 流程 | 流程列表、受众和有效期筛选 |
| `/admin/procedures/:id` | 编辑流程 | 步骤排序、材料、地点/部门关联、预览发布 |
| `/admin/guides` | 指南 | 主题列表、状态/核验筛选 |
| `/admin/guides/:id` | 编辑指南 | 结构化字段、正文、关联和来源 |

新建路由可复用编辑表单。`/admin/merchants`、`/admin/ai` 在 MVP 不显示，避免形成已开放商家认领或额外 AI 管理入口的误解；普通学生登录、个人中心和群聊入口不在公开导航中。

### 8.1.1 评委端边界

评委端不是管理员后台的精简版，而是独立会话域：`/judge` 只能看到自己所在轮次的名单、自己的评分和已公布结果，不能查看其他轮次评委账号、其他评委的逐项打分或后台配置。评委账号按轮次生成，初赛、复赛、决赛可以使用完全不同的人；同一评委若跨轮执评，会拿到两个独立账号。组织者关闭某一轮评分后，该轮成绩锁定，未提交评分的选手按弃权处理。复赛/决赛名单由上一轮晋级结果随机抽签生成，管理员可在列表中上移/下移手动调整；轮次结束前调整只影响出场顺序与同分时的先后。

### 8.2 工作台优先级

工作台按需处理顺序展示：

1. 已过期但仍发布的强时效内容。
2. 临近报到、临时公告等高风险内容。
3. 待处理纠错反馈。
4. 到达复核日期的地点、商铺和社团。
5. 草稿和近期修改。

访问量不应压过内容正确性任务。数据不足时不展示虚假趋势图。

### 8.3 编辑与发布流程

```text
新建草稿
  -> 填写结构化字段与正文
  -> 关联地点/部门/来源
  -> 校验必填项、坐标系、有效期
  -> 预览公开效果
  -> 发布
  -> 到期提醒/用户反馈/主动复核
  -> 更新并重新核验，或归档下架
```

发布校验应按类型执行，例如地点必须有坐标，招新信息必须有状态或有效期，强时效流程必须有适用年份/复核日期。

## 9. 命名、分类与 URL 规范

### 9.1 命名规则

- 主名称优先使用当前官方全称，学生常用简称作为别名。
- 地点名称不足以定位时补充区域，如“XX 服务点（东区）”，不把完整地址塞入标题。
- 部门用正式名称，简称单独存储。
- 指南标题使用任务语言，如“校园网如何开通”，避免“相关事项说明”等模糊标题。
- 商铺不添加未经证实的“官方”“指定”“第一”等词。

### 9.2 Slug 规则

- 公开 URL 使用稳定、可读的 ASCII slug；名称变化不轻易更换 slug。
- slug 全局或实体内唯一，使用小写字母、数字和连字符。
- 发生变更时保留旧地址重定向，分享链接不直接暴露数据库自增 ID。

### 9.3 初始分类建议

地点分类首版建议：校门、宿舍、教学楼、行政服务、图书馆/学习、食堂/餐饮、运动、医疗、快递、外卖取餐、交通、生活服务、周边商铺、其他。

指南主题首版建议：报到准备、住宿、学习、校园卡、校园网、快递外卖、安全健康、交通、校内办事、校园生活。

最终分类应在首批内容盘点后收敛；不为只有一个条目的类别增加一级入口。

## 10. 埋点与搜索分析边界

MVP 如启用匿名统计，仅建议记录：页面类型、匿名会话、站内搜索词、筛选类别、无结果事件、外部导航点击、纠错入口和 PWA 安装事件。不得默认记录精确经纬度、反馈正文、联系方式或可还原个人路线的连续位置数据。

搜索词分析只用于补充别名和缺失内容。统计不可用时不影响任何核心页面。

## 11. IA 验收清单

- 六类核心任务在移动首页都有明确入口。
- 地图、地点详情、流程和指南之间存在双向可达关系。
- 所有公开详情页均有来源/核验信息和纠错入口。
- 所有内容类型均定义加载、空、失败、离线和下架状态。
- 微信内深链接无需登录即可落到目标内容。
- 拒绝定位和地图脚本失败有在线文本降级路径；完全离线时有明确说明、返回和重试路径。
- 桌面约 280px 列表/地图并列和移动底部抽屉均通过双向联动、密集标签、数字聚合、键盘与触控验收。
- 地图使用项目自有颜色和 Lucide 图标，不包含第三方地图工作台专有图标、截图切图或视觉复刻。
- 后台一名维护者能从工作台发现待复核、将过期和待纠错内容。
- 学生账号、AI 检索、商家认领和推广管理入口在 MVP 不出现。
- 商铺与其他地点共用可维护的空间模型，但在文案和来源上明确其商业属性。
- 路由名称稳定、slug 为 ASCII，并可支持后续重定向。
