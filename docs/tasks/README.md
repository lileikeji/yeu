# 任务台账

> 用途：让跨越多轮、可能被中断的任务**不依赖对话记忆**。隔几周回来，读任务文件就能接上进度。
>
> 只放技术决策与工程进度，不记录协作流程。

## 怎么用

**开工前**
1. 读本文件的「任务索引」，看有没有相关或搁置中的任务
2. 若有，先读该任务文件的「下一步」小节

**任务中**
- 遇到改变方向的决定 → 追加到「决策记录」
- 被中断 → 更新「状态」为 `搁置`，并在「下一步」写清楚恢复时该做什么

**收尾时**
- 状态改 `已完成`，补「遗留缺口」
- 可复用的技术判断提炼到 [`../rules/LESSONS.md`](../rules/LESSONS.md)

## 状态取值

| 状态 | 含义 |
| --- | --- |
| `规划中` | 方案已定，未动代码 |
| `进行中` | 正在改 |
| `等待审核` | 代码完成、PR 已提，等合入 |
| `搁置` | 主动暂停，可能恢复（**必须写清下一步**） |
| `已完成` | 已合入或已交付 |
| `已放弃` | 不做，写明原因 |
