# 仰恩大学新生入学指南系统 PRD

> 文档版本：0.1
> 文档状态：初稿，供产品确认与 MVP 实施
> 维护主体：个人/学生团队
> 目标用户：仰恩大学本科与专升本新生
> 产品暂定名：仰恩新生指南

## 1. 产品概述

### 1.1 背景

新生在入学前后需要从学校官网、公众号、社交平台、群聊和地图应用中反复寻找信息。信息来源分散、更新时间不一，校内地点又常缺少精确标注，导致报到、找宿舍和教学楼、办理校园卡与网络、收取快递外卖等高频任务成本较高。

本系统以“可搜索、可定位、可追溯”为核心，将校内地点、办事流程和新生生活信息整理为适合手机浏览的结构化指南。首版由个人或学生团队维护，并为未来与学校官方合作预留内容审核、来源管理和权限扩展能力。

### 1.2 产品定位

一个无需登录即可使用、以精细校园地图为核心的仰恩大学新生信息工具，同时适配普通移动浏览器、PWA 安装和微信内访问。

首版必须清晰标注“非学校官方平台”，不冒用学校官方身份。涉及校规、收费、报到日期等权威信息时，以学校当前发布内容为准，并展示来源和核验日期。

### 1.3 核心价值

1. **地图找得到**：地点不只显示名称，还提供校区、楼栋、楼层/房间、开放时间、联系方式、现场提示及关联事项。
2. **流程做得完**：把报到和常见事务拆成顺序清晰、可执行的步骤，并指出材料、地点、时间和负责部门。
3. **信息信得过**：重要内容附来源、核验日期和官方属性，过期或待核实信息不伪装成确定事实。
4. **手机用得顺**：优先满足新生到校当天单手操作、弱网浏览、微信分享和外部地图导航等场景。

## 2. 产品目标与衡量指标

### 2.1 MVP 目标

- 建成可用的校内及学校周边地图，覆盖新生高频地点并提供详细标点信息。
- 覆盖报到流程、宿舍/教学楼、校园卡与网络、快递外卖、周边商铺、社团招新六类核心内容。
- 提供单人可维护的后台，使地点和指南不依赖修改代码即可更新、预览、发布和下架。
- 在不要求学生注册的前提下，完成从“有问题”到“找到地点或答案”的主要路径。
- 支持 PWA 基本能力，并在微信内置浏览器中可正常阅读、搜索、定位与分享。

### 2.2 建议上线指标

首轮上线后以匿名、聚合数据评估，具体目标值可在测试期建立基线后调整。

| 指标 | 定义 | MVP 建议目标 |
| --- | --- | --- |
| 核心地点覆盖率 | 已发布且已核验的高频地点 / 清单内高频地点 | 100% |
| 核心内容完整率 | 六类核心内容中已通过内容检查的条目占比 | 100% |
| 地点查找成功率 | 测试用户在 60 秒内找到指定地点详情 | 不低于 90% |
| 报到流程完成率 | 测试用户能说清下一步、材料和地点 | 不低于 90% |
| 内容可追溯率 | 重要事实至少关联一个来源或核验记录 | 100% |
| 移动端可用性 | 核心流程在目标设备/浏览器测试通过 | 100% |
| 严重地图错误 | 坐标错误导致用户到达错误区域 | 上线阻断，必须为 0 |

不以注册用户数、停留时长或推广点击率作为 MVP 成功标准。

## 3. 用户与使用场景

### 3.1 核心用户

| 用户 | 特征 | 主要需求 |
| --- | --- | --- |
| 本科新生 | 首次到校，对校园和流程不熟悉 | 报到、宿舍、教学楼、生活服务 |
| 专升本新生 | 部分流程或安排可能与普通本科不同 | 快速识别适用于自己的流程与地点 |
| 新生家长 | 短时陪同，主要通过手机访问 | 校门、报到点、停车/落客、住宿与周边服务 |
| 内容维护者 | 首版仅一名管理员 | 快速录入、核验、发布、纠错和下架内容 |

### 3.2 典型场景

- 到校前查看报到材料、时间、入口和完整步骤。
- 到校后定位宿舍、教学楼、食堂、医务室或行政办公室。
- 查询校园卡领取/补办、校园网开通和常见故障处理。
- 判断快递在哪个站点领取、外卖可送至哪个校门或指定点。
- 查看学校周边商铺的距离、营业时间、联系方式和客观描述。
- 浏览社团介绍、招新时间、活动地点和公开联系方式。
- 发现信息有误时提交纠错，管理员核实后更新。

## 4. 产品原则

1. **地图优先**：从首页和内容详情都能快速回到地图；地点详情与办事内容互相链接。
2. **游客优先**：核心功能无需账号、无需授权手机号、无需关注公众号。
3. **事实优先**：官方来源优先于转载，现场核验优先于未经证实的网络描述。
4. **新生语言**：避免只使用校内简称；首次出现时给出全称、位置和用途。
5. **渐进增强**：定位、PWA 安装、系统分享等能力不可用时仍能完成核心任务。
6. **商业内容隔离**：未来推广必须显著标识，不影响自然排序和必要公共信息。

## 5. MVP 范围

### 5.1 P0：必须上线

#### A. 校园与周边地图

- 默认展示校园范围和关键地点；桌面端采用约 280px 地点列表与右侧地图并列，移动端采用近全屏地图与底部抽屉。
- 按校门、宿舍、教学楼、行政服务、食堂、运动、医疗、快递、外卖点、交通、周边商铺等类别筛选。
- 支持关键词搜索地点名称、别名、用途和常见问法。
- 地点列表与地图标点双向联动：选择任一侧后，另一侧同步高亮并保持搜索、筛选和返回上下文。
- 点击标点显示摘要卡片，展开后进入完整地点详情。
- 常态图钉使用项目自有类别色和 Lucide 图标；选中态、标签和详情浮层不得复制第三方地图工作台的专有视觉素材。
- 地点名称按 zoom 分级显示并执行标签碰撞隐藏；低 zoom 使用显示数量的聚合点，不能依靠点位互相覆盖或随机隐藏表达密度。
- 地点详情至少包含：名称、类别、校内/周边属性、详细位置、坐标、图片（如有）、开放时间（如适用）、联系电话（如公开）、文字到达提示、最后核验时间和来源。
- 支持从指南、流程、部门或社团详情跳转到关联地点，并在地图上高亮。
- 获取用户定位前说明用途；拒绝授权后仍可浏览地图和手动搜索。
- 提供“在外部地图中打开/导航”能力；无法唤起时复制地址或展示文字路线。
- 区分官方地点、学生团队核验地点和待核实信息；待核实内容默认不作为关键流程唯一依据。
- 地图标点聚合、筛选状态和详情面板不得互相遮挡关键操作。
- 图钉、聚合、列表/地图联动、桌面浮层、移动端抽屉及降级行为以 [MAP_INTERACTION_SPEC.md](./MAP_INTERACTION_SPEC.md) 为验收基线。

#### B. 报到流程

- 提供按顺序排列的报到步骤，明确时间、地点、材料、负责部门和注意事项。
- 本科与专升本存在差异的内容必须加受众标签；没有差异时共用流程。
- 每个涉及地点的步骤可一键在地图中查看。
- 日期或安排尚未发布时显示“等待学校通知”，不得沿用旧年份作为当年事实。
- 首版不将流程完成状态同步到服务器；如提供勾选，仅保存在当前设备本地。

#### C. 新生指南内容

- 校园卡：领取、充值/消费、挂失/补办及服务地点。
- 校园网络：开通、连接方式、常见问题、服务渠道；不收集学生密码。
- 宿舍与教学楼：命名、区域、用途、开放规则和到达提示。
- 快递与外卖：站点、可收取范围、营业时间、校门/取餐点规则及变更提示。
- 校园简介、常用部门、校内事项与紧急/生活服务信息。
- 指南详情展示适用人群、阅读时间、正文、关联地点/部门、来源和核验日期。

#### D. 周边商铺

- 在地图和列表中展示学校周边对新生有用的商铺与服务。
- 首版信息为编辑维护的客观资料，包括类别、地址、营业时间、电话、价格说明（若来源可靠）、图片和核验日期。
- 首版不支持商家自行注册、认领、付费推广、优惠券、交易、评分或用户评论。
- 商家条目不得暗示学校背书；无法核实或已停业的内容应下架或显著标记。

#### E. 社团与招新

- 提供社团分类、简介、活动方向、招新时间、公开联系方式和活动/招新地点。
- 招新信息有有效期，过期后自动或人工转为“本期已结束”。
- 联系方式只展示社团明确同意公开的信息，个人敏感信息需脱敏或避免收录。

#### F. 站内搜索与反馈

- 提供普通关键词搜索，覆盖地点、流程、指南、部门、社团和周边商铺。
- 结果按类型分组并显示能帮助判断的摘要；无结果时给出分类入口和纠错反馈入口。
- AI 问答、向量检索和个性化推荐不属于 MVP。
- 用户无需登录即可提交纠错，至少包含关联页面、问题类型、说明及可选联系方式。
- 后台可查看和处理反馈；公开页面不直接展示未经审核的用户提交内容。

#### G. 单人维护后台

- 管理员通过独立后台登录；MVP 仅一个管理员账号，不建设复杂角色系统。
- 可管理地点、类别、指南、报到流程、部门、社团、周边商铺、来源和反馈。
- 内容支持草稿、已发布、已归档状态，发布前可预览。
- 地点编辑支持地图选点和经纬度输入，并记录坐标系，避免直接混用 WGS-84、GCJ-02、BD-09。
- 可关联内容与地点、部门和来源，填写最后核验日期。
- 删除已公开内容优先使用归档/下架，避免误删和失效链接。
- 至少保留最近修改时间；完整版本历史与多人审批可在后续实现。
- 管理端不要求适配微信，优先桌面浏览器，但关键操作在手机上不可完全失效。

#### H. PWA 与微信内访问

- 提供 Web App Manifest、应用图标、独立显示模式和可安装条件。
- 只预缓存专用断网说明页及其必要 CSS、图标和字体，不预缓存任何 JavaScript；公开页面导航与内容 API 在 V1 均使用 `NetworkOnly`。
- 断网导航统一回退到 `/offline.html`，说明当前无法取得最新内容并提供重试/返回入口；V1 不承诺离线浏览最近访问的地点或指南。
- 已发布内容的有限时长离线缓存属于后续增强，只有在版本失效、缓存时间展示和强时效内容排除规则完成后才可启用。
- 微信内置浏览器可完成首页、地图浏览、搜索、详情阅读、定位授权和链接分享。
- 无法在微信中直接唤起第三方导航或安装 PWA 时，提供“在浏览器打开”、复制地址或文字指引等降级路径。
- 页面具备可分享标题、摘要和缩略图；深链接打开后能定位到对应地点或内容。

### 5.2 P1：MVP 质量允许时加入

- 地图常用类别快捷筛选和“新生最常去”精选地点。
- 报到清单在本机保存勾选状态，并支持清空。
- 最近访问、收藏地点或指南，仅存本机且提供清除入口。
- 内容有效期提醒和后台待复核列表。
- 站内公告/紧急变更横幅，由管理员设置生效和失效时间。
- 匿名访问统计与站内搜索词统计，不采集精确位置轨迹。

### 5.3 明确非目标

以下内容不进入 MVP，不应阻塞首版发布：

- 学生注册登录、学号认证、跨设备同步和个性化档案。
- AI 问答、AI 搜索、聊天机器人和基于个人信息的推荐。
- 商家认领、商家后台、优惠券、广告竞价、推广位售卖和在线支付。
- 用户评论、评分、发帖、私信、群聊及完整社区功能。
- 校园官方业务系统替代品，例如缴费、选课、成绩、门禁或校园卡交易。
- 室内实时导航、实时公交、外卖或快递物流接口。
- iOS/Android 原生 App 和微信小程序；首版为适配微信访问的 Web/PWA。
- 多管理员角色、部门自助发布及学校级审批流。

## 6. 用户故事与验收标准

### US-01 查找校内地点

**作为**刚到校的新生，**我希望**按名称或用途找到宿舍/教学楼，**以便**确认位置并前往。

验收标准：

- 输入正式名称或已配置别名后，目标地点出现在搜索结果中。
- 点击结果后，地图高亮唯一目标并展示名称、详细位置和到达提示。
- 桌面列表项和图钉保持双向高亮；移动端在底部抽屉展示同一地点摘要，返回后上下文不丢失。
- 用户可打开完整详情，也可尝试外部导航。
- 拒绝定位权限不影响搜索和地点详情。
- 分享后的链接在另一台设备打开时仍指向同一地点。

### US-02 浏览地图分类

**作为**不熟悉校园称呼的新生，**我希望**按“食堂”“快递”等用途筛选，**以便**发现附近可用地点。

验收标准：

- 选择一个或多个支持的类别后，只显示匹配标点，并明确当前筛选条件。
- 可一键清除筛选并恢复默认视图。
- 空结果说明原因，不显示空白地图或伪造推荐。
- 缩放或打开标点详情时，筛选状态不应意外丢失。
- 校园全览时密集标签不出现不可读重叠；低 zoom 显示数字聚合，点击聚合点后缩放至成员范围或显示成员列表。

### US-03 完成报到流程

**作为**本科或专升本新生，**我希望**看到适用于自己的报到步骤，**以便**准备材料并按顺序办理。

验收标准：

- 用户能选择或识别“本科”“专升本”受众，差异步骤有清晰标签。
- 每一步至少说明动作；适用时同时说明材料、时间和地点。
- 点击地点可跳转地图并高亮，不要求用户重新搜索。
- 未确定的时间或规则明确标为待通知，并附学校官方信息入口。
- 本地清单数据（如实现）在退出页面后仍保留，且能由用户清除。

### US-04 办理校园卡与网络

**作为**新生，**我希望**找到校园卡和网络办理说明，**以便**独立完成操作或找到服务窗口。

验收标准：

- 搜索“校园卡”“校园网”“Wi-Fi”等常见词可找到对应指南。
- 指南按步骤说明办理条件、入口、服务地点和常见问题。
- 页面不要求、保存或诱导提交校园卡密码、网络密码等敏感信息。
- 规则性内容显示来源及最后核验日期。

### US-05 查快递与外卖地点

**作为**住校新生，**我希望**知道快递和外卖在哪里领取，**以便**避免跑错校门或站点。

验收标准：

- 地图可按快递站点和外卖取餐点筛选。
- 详情显示服务范围、时间、校门/区域和到达提示；不确定信息显著标记。
- 临时调整可由管理员发布公告，并能关联受影响地点或指南。

### US-06 浏览周边商铺

**作为**新生或家长，**我希望**查看学校周边常用商铺，**以便**比较位置和基本服务信息。

验收标准：

- 用户可按类别查看商铺，并从列表或地图进入同一详情。
- 详情区分编辑资料、商家公开信息与官方来源，不显示虚构评分。
- MVP 页面不出现商家认领、购买优惠或付费置顶入口。
- 如未来存在推广内容，必须与自然结果清楚区分；该能力在 MVP 保持关闭。

### US-07 查看社团招新

**作为**希望参加校园活动的新生，**我希望**按兴趣浏览社团和招新信息，**以便**找到联系和报名方式。

验收标准：

- 社团可按类别筛选，详情展示简介、招新状态和公开联系方式。
- 有地点的活动可跳转地图。
- 过期招新不继续显示为“进行中”。
- 未经同意的个人手机号、微信号等不公开展示。

### US-08 提交纠错

**作为**发现错误的访客，**我希望**不用注册即可反馈，**以便**帮助维护者修正信息。

验收标准：

- 从内容详情发起反馈时自动带上条目和当前页面地址。
- 必填项不足时给出明确提示，成功提交后给出确认状态。
- 管理员后台可按待处理/已处理查看，反馈内容默认不公开。
- 接口具备基础限流和垃圾提交防护，不将联系方式写入公开日志。

### US-09 管理员发布地点

**作为**唯一内容维护者，**我希望**录入并预览一个地点，**以便**确认坐标和描述无误后发布。

验收标准：

- 未登录不能访问管理数据或执行写操作。
- 地点缺少名称或类型时不能发布；地点实体只有在关联至少一条有效来源，并具备已核验、核验时间不晚于当前时间的 WGS84 坐标后才能发布。尚无可靠坐标的资料保留为地点草稿；确需先公开的纯文字说明应作为指南内容发布，不能伪装成可导航地点。
- 预览与公开页采用相同主要字段和关联关系。
- 发布后公开端可搜索且地图能显示；下架后不再出现在搜索和默认地图中。
- 修改时间、核验时间与来源可被管理员查看。

### US-10 在微信或弱网环境使用

**作为**通过微信收到链接的新生，**我希望**直接打开相关信息，**以便**无需安装 App 也能使用。

验收标准：

- 微信内打开深链接直接到对应内容，不强制跳首页或登录。
- 核心文字在地图脚本或定位失败时仍可阅读。
- 离线时进入明确的断网说明页，不把缓存正文伪装成最新内容，并提供重新加载和返回入口。
- 不支持的安装或导航动作提供清楚、可执行的替代方式。

## 7. 页面级验收与发布定义

### 7.1 通用页面状态

每个列表、详情和地图页面必须处理：加载中、无数据、请求失败、离线、内容不存在/已下架五类状态。错误状态应提供重试或返回相关入口，不暴露服务器堆栈和敏感信息。

### 7.2 内容发布 Definition of Done

一个核心内容条目只有满足以下条件才可视为可发布：

- 标题、分类、摘要、正文或必要结构化字段完整。
- 受众和时效性已确认；存在截止日期时配置过期行为。
- 涉及地点的关联和坐标已在地图上人工检查。
- 重要事实附来源；来源链接、平台、是否官方和访问日期已记录。
- 图片具备使用授权或明确来源，不包含不必要的个人信息。
- 手机窄屏、微信内浏览器和桌面后台预览通过。
- 不确定信息使用明确措辞，未把旧年份安排当作当前安排。

### 7.3 MVP 整体验收

- 六类核心任务均有至少一条从首页可达、无需登录的完整路径。
- P0 地点清单全部完成两次坐标核验，其中至少一次为现场、可信地图或官方资料交叉核验。
- 管理员可独立完成“新建草稿 -> 预览 -> 发布 -> 更新 -> 下架”。
- 核心公开页面在主流 Android/iOS 浏览器、微信内置浏览器和桌面现代浏览器通过测试。
- 不同坐标系转换经样本点比对，外部导航目的地不发生明显偏移。
- 地图通过 [MAP_INTERACTION_SPEC.md](./MAP_INTERACTION_SPEC.md) 中布局、密度、双向联动、键盘/触控和失败降级验收。
- 严重安全问题、敏感信息泄露、阻断级无障碍问题和失效核心链接为 0。

## 8. 内容与数据治理

### 8.1 来源优先级

1. 仰恩大学官网、官方公众号、正式通知和校内部门公开信息。
2. 现场核验、学校公开地图和可确认的部门答复。
3. 主流地图平台及商家公开页面。
4. 主流内容平台、社团公开账号和学生经验分享，仅用于线索或非权威建议。

低优先级来源不能覆盖高优先级来源中的明确事实。存在冲突时，公开页应采用更权威且更新的内容；无法判断时标记待核实。

### 8.2 时效规则

- 报到时间、缴费、校规、网络办理等强时效内容应设置有效年份或复核日期。
- 商铺、营业时间、联系方式和社团招新建议至少每学期复核一次。
- 过期招新、临时公告和报到批次应自动失效或进入后台待处理列表。
- 页面展示“最后核验于”，而非用“最新”“永久有效”等无法保证的措辞。

### 8.3 合规边界

- 尊重学校名称、校徽、地图、照片和各平台内容的知识产权；未获授权前不暗示官方合作。
- 不大段搬运平台文章或用户内容，优先结构化整理事实并保留引用链接。
- 只收集完成反馈和基础统计所需的最少数据，提供隐私说明与联系方式。
- 不公开学生宿舍具体个人信息、门禁细节、个人课表或可能带来安全风险的位置数据。

## 9. 非功能需求

### 9.1 性能

- 移动网络下优先加载可交互界面与核心文字，地图和图片采用按需加载。
- 地图大量标点使用聚合或分层加载，常规拖动与缩放保持可用。
- 图片使用合适尺寸和现代格式，避免地图首屏被大图阻塞。
- 建议目标：生产环境核心公开页 Lighthouse 性能分数不低于 80，其他三项不低于 90；以中端移动设备和受控网络测试为准。

### 9.2 可用性与无障碍

- 核心操作可通过键盘完成，图标按钮具备可读名称。
- 不只用颜色区分地点状态或类别，文字与背景满足基本对比度要求。
- 触控目标适合单手操作；底部导航、地图控件和详情面板不互相遮挡。
- 正文支持系统字体放大，最长名称不溢出容器。

### 9.3 安全与隐私

- 后台强制 HTTPS，密码使用安全哈希，不在前端或仓库写入密钥。
- 管理写接口具备身份校验、CSRF/来源防护、输入校验、上传类型限制和速率限制。
- 地图定位默认只在用户设备上用于展示，不存储完整位置轨迹。
- 反馈中的联系方式只对管理员可见，并设置保留与删除策略。
- 依赖、备份与管理员登录应有基础监控；后续上线前完成一次恢复演练。

### 9.4 兼容性

- 支持当前及前一个主要版本的 Chrome、Edge、Safari，以及常见 Android WebView 和微信内置浏览器。
- 不把仅某一平台支持的 API 作为唯一入口。
- Windows/Linux 桌面端保障后台使用，公开端以手机竖屏为优先。

## 10. 依赖与假设

- 校内地图、地点清单和照片需通过官网、公开平台与现场核验逐步建立；当前尚无学校提供的权威完整数据集。
- 地图供应商、瓦片授权、坐标系、配额和商用条款需在实施前确认。
- 服务器后续使用用户的宝塔 Linux 环境，具体配置、域名、备案、证书和备份方案另行确认。
- 首版内容更新由一名管理员承担，因此数据模型和发布流程必须降低重复录入成本。
- 目前不依赖学校统一身份认证、校园系统接口、商家接口或 AI 服务。

## 11. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 校内地图资料不完整或坐标偏移 | 用户走错地点，损害信任 | 建立 P0 地点清单；记录坐标系；双重核验；提供纠错入口 |
| 官网和平台信息相互冲突 | 流程错误或内容过期 | 来源分级；显示核验日期；强时效内容设置失效日期 |
| 单人维护内容量过大 | 更新不及时 | 首版严格聚焦高频内容；模板化录入；后台复核提醒 |
| 微信浏览器限制定位、下载或跳转 | 核心流程中断 | 逐项能力检测；提供复制地址、文字路线和外部浏览器提示 |
| PWA 离线时误展示旧通知 | 新生把过期安排当作当前事实 | V1 页面导航和内容 API 使用 `NetworkOnly`；只回退断网说明页，内容缓存后续单独设计版本失效机制 |
| 非官方身份引起误解 | 法务与信任风险 | 显著非官方声明；不冒用校徽；权威内容链接原始来源 |
| 商铺信息被认为广告或背书 | 公信力下降 | MVP 不收费不认领；客观字段；未来推广显著标识并留存审核记录 |
| 公开联系方式涉及隐私 | 对个人造成骚扰或风险 | 只收录经同意公开的组织联系方式；优先官方渠道；支持撤回 |
| 地图服务成本或条款变化 | 服务不可用或超预算 | 封装地图适配层；监控配额；准备可替换方案与文字列表降级 |

## 12. 待确认事项

以下事项不阻塞文档和脚手架，但应在地图开发或内容采集前确定：

- 产品正式名称、域名、视觉标识及“非官方”声明文案。
- 校区边界、主要入口和第一批 P0 地点清单。
- 地图供应商及其在微信 WebView、PWA、生产域名下的授权与配额。
- 本科与专升本报到流程的真实差异，以及当年官方通知发布时间。
- 图片来源、现场采集计划和是否获得学校相关素材授权。
- 反馈联系方式保留周期、隐私政策主体和内容纠纷处理渠道。

## 13. 后续方向

- 商家认领、优惠和推广位：必须在商家身份核验、广告标识、排序规则、投诉处理与账务能力就绪后开放。
- 学生账号与 AI 检索：在内容库稳定、隐私方案明确后建设，用于跨设备收藏、个性化回答和来源可追溯的问答。
