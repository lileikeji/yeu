# 系统体检与优化实施计划（2026-07-15）

> 适用阶段：V0.3 内容与办事流程 Alpha → V0.9 新生内测  
> 体检范围：工程质量、数据可信度、用户体验、安全、性能、发布与运维  
> 本文是执行计划，不替代 PRD、路线图、内容政策或部署手册。

## 1. 结论摘要

系统已经具备可用 Alpha 的主要骨架：Nuxt 前后台、SQLite/Drizzle 数据层、内容与地点维护、结构化办事流程、地图双 provider、管理员会话、审核日志、发布约束、PWA 和较完整的自动化测试均已落地。

当前主要矛盾已经不是“缺少更多页面”，而是以下四项：

1. 当前工作区改动较多，尚未形成可重复验证的稳定发布基线。
2. 地图地点、2026 当年信息和周边资料尚未全部达到公开发布所需的核验门槛。
3. 自动化测试偏服务层和静态规则，缺少真实浏览器、手机、微信、无障碍和性能验收。
4. 部署文档已经覆盖安全、备份和恢复要求，但监控告警、自动备份、恢复演练等生产闭环仍需实际执行并留下记录。

因此，下一阶段应先收口和验证，再进入小范围内测；暂不把学生账号、AI 问答、商家认领和复杂多角色权限列为近期目标。

### 2.1 当前两个失败项

#### A. 后台内容字段测试未同步

后台内容表单已经增加 `address`、`contactUrl`、`profileUrl`，而 `scripts/admin-ui-config.test.ts` 仍使用旧字段集合。

处理方式：

1. 确认三个字段确实属于内容后台的长期数据契约。
2. 检查前端表单、共享类型、序列化、服务层和公开展示是否一致。
3. 在确认实现无误后更新测试期望；不能只删除断言绕过失败。

#### B. 数据一致性统计基准过期

当前完整种子库生成：

- 来源总数：98；测试预期：84。
- active 来源：91；测试预期：77。
- unavailable 来源：7；与测试一致。
- 已发布内容 58、流程 5、流程步骤 23、高德草稿地点 76；均与测试一致。

处理方式：

1. 审核新增的 14 条来源是否均为有意新增。
2. 按标准化 URL、标题、内容关联和所有权标记检查重复或漂移。
3. 确认数据正确后，同步测试和路线图中的验收库统计。
4. 如果发现重复或无效来源，应先清理种子定义，不能直接把测试数字改成 98/91。

## 3. 已有优势与应保留的设计

- 公共内容无需学生登录，符合 MVP 的低门槛目标。
- 内容、来源、地点、流程和反馈均有后台维护入口。
- 地点正式发布要求有效来源、WGS84 坐标和独立双重核验，发布门槛清晰。
- 高德授权工作地图草稿与正式发布地点保持区分，避免用 GCJ-02 草稿绕过核验。
- 管理员会话包含安全 Cookie、CSRF、来源校验和登录限流。
- 关键后台写操作进入数据库审计日志。
- 数据库迁移、发布约束、导入幂等性、数据一致性和 PWA 均已有自动化检查。
- 部署文档明确了单 SQLite 实例、原子 release、备份、恢复和回滚边界。

后续优化应围绕这些边界扩展，不应为了赶进度降低坐标、来源或发布门槛。
