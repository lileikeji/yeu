# 校园地图精度审计

审计日期：2026-07-14。范围仅包括当前仓库、学校官网公开页面和 OpenStreetMap 官方只读 API；未调用高德工作地图私有接口，也未使用登录 Cookie。

## 1. 结论

现有公开数据不足以生成任何新的楼栋入口导航点。当前必须继续保持以下三类数据相互隔离：

- 已完成双重现场核验的 WGS84 点才是导航点；
- 学校官网平面图与 47 项图片热点只用于名称和校内相对方位对照，不产生地理坐标或入口结论；
- OSM relation 和道路只表示社区测绘参考，不证明校名、楼名、入口或通行状态。

没有新增 OSM 建筑/道路可视化覆盖层。原因不是接口不可用，而是校界内只有两条无名且陈旧的道路；把它们加粗绘制会制造精度已经提高的错误印象。

## 3. 官网平面图来源快照

学校官网平面图是较完整的公开校内方位资料，但它是示意图，没有 CRS、世界文件或地理控制点。按维护者当前要求，项目恢复了经过字节核验的原图快照与 47 项图片相对热点，并保留官网来源和非导航说明；图片热点仍不得转换为经纬度、入口或通行结论，正式公开授权仍须发布前确认。

运行以下命令只读校验官网图片是否发生变化，以决定是否重新核对文字索引和内部研究记录：


尺寸、内容哈希、ETag 或 Last-Modified 任一变化都会失败。失败后必须重新审查本地快照、47 项编号热点和内部研究记录，不能只更新哈希让检查通过；该命令只核对上游资源，不自动覆盖 `public/` 中的已审核快照。

## 4. 高德工作地图导出

最初的 Excel 导出包含 76 个标记和 8 个区域，但 G 列编码不是可直接使用的经纬度。随后在用户授权登录态下取得 WIA `sparseList` 响应，已获得 76 个 GCJ-02 标点中心坐标，以及 8 个区域的中心、包围框和 `subPointIds`。标点可以作为“工作地图来源、未独立现场核验”的草稿层显示；区域包围框不是原始轮廓，不能绘制为多边形。

WIA 前端代码表明真实区域轮廓由 `resource/render/shapeBatch`/资源详情响应返回，并由 `subPointIds` 关联。用户授权提供的 8 份响应已经覆盖全部区域，`data.resources[].data.polygonInfo` 给出了闭合 WKT 多边形；这些原始 GCJ-02 顶点按原值写入 seed 并明确标注 CRS，由高德直接绘制，避免再次进行网络坐标转换。前台只绘制闭合边界线，不使用会拦截底图商铺点击的填充面。

因此授权坐标导入只能接收明确提供的坐标、坐标系、点位角色和证据说明，并生成待审核观测；它不能直接写入 `verified`。

## 5. 下一轮精度来源

真实导航精度只能由以下任一证据补齐：

1. 高德工作地图提供的授权 `shapeBatch` 区域顶点或其他坐标导出，保留原 GCJ-02 坐标系并进入人工审核。
2. 现场浏览器采点：5 至 7 个不高于 25 米的 WGS84 修复，至少持续 12 秒，再按同一角色、20 米内、时间独立的双证据规则审核。
3. 学校发布带 CRS 或地理控制点的 GIS/KML/GeoJSON/测绘数据；普通示意图、截图和地址文字均不满足该条件。
