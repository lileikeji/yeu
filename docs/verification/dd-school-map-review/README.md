# dd-school-map 项目调研（2026-11-07）

> 一次性调研记录。对象：[gitee.com/bananana12138/dd-school-map](https://gitee.com/bananana12138/dd-school-map)——同校（仰恩大学）的另一个校园地图项目。两个分支均浅克隆到本地实际查看代码，PR 亦拉取核对，非仅读 README。

## 项目概览

技术路线与 yeu 相反：**Python + MySQL + 原生 JS，零构建**。

- 纯原生 JS + Canvas 2D，无 npm/打包步骤；`python -m app.serve` 单命令起服务
- 数据以 MySQL 库 `schoolmap` 为准；`seed/` 种子开箱还原 55 标点
- 航拍正射图（5376×4352）作底图 + 高德 JS API 定位（GCJ-02）
- 接入"掌上叮叮"校车真实 GPS（12 秒拉取、WGS84→GCJ-02→像素三级转换、60 米道路吸附兜底）

## master 分支（地图模块）优点

1. **零构建、开箱即用**——单人维护成本极低，改完刷新即生效
2. **种子数据机制**：schema.sql + init.sql（仅有 mysql 客户端即可还原）+ JSONL + SHA-256 校验；`export/import/status/verify` 四个子命令；"改完标点提交前先 export"的维护约定
3. **真实数据接入文档化**：接入记录、busapi 接口评估、运营统计脚本齐全
4. **并发/冲突处理**：标点按对象版本保存，冲突三方对照逐项选择；10 人并发写测试 + 前端状态合并测试
5. **安全意识**：凭据全不入库（.example 模板代替）；匿名限流可配；公开写接口 Origin 同源校验；管理员首次设密码仅限服务器本机；公网建议 Caddy 反代 + 后端绑 127.0.0.1
6. **备份闭环**：`app.backup create/verify/restore` 带校验和，恢复强制新库名+新目录，不覆盖在用数据

## news 分支（资讯模块）优点

抓学校官网通知/讲座 + LLM 评分筛选 + 活动时间地点解析。

1. **特征开关默认关闭**：`SCHOOLMAP_NEWS` 不设时 `/api/news` 一律 404、采集线程不启动；地图详情弹窗对缺失接口**静默隐藏区块**（404→隐藏，不报错）
2. **LLM 双评可信流程**：每条独立评两次取平均；按信源分级设门槛（T1 官方 55 / 学生投稿 62 / T2 媒体 70）；评分理由落库可查 + 申诉通道 + 人工改判；不配 Key 时降级为"只采集不筛选"照常展示
3. **活动地点解析不瞎猜**：别名表精确 → 别名子串（≥3 字防"楼"误命中）→ 完整地名；未命中留空交人工、多命中标 `ambiguous`，**不做相似度猜测**
4. **学生投稿通道**：投稿返回查询码查进度；5 次/分/IP 限流、队列上限 200；管理员审核后才公开
5. **测试真实可跑**：news 单测 107 项不联网、不需要 MySQL（store 用 mock、解析用本地 HTML 样本）。本机实测 5 个报错均为缺 `pymysql` 的 import 失败，装依赖即绿
6. **模块边界**：新增 7 张表（news_source/news_article/news_event/news_review/news_appeal/news_submission/venue_alias），不改地图现有任何表

## 对 yeu 的可借鉴点

| 借鉴点 | 落点建议 |
| --- | --- |
| 种子数据带校验和 + export 维护约定 | 比 SQLite 数据文件直接随仓库走更适合多人协作 |
| 详情弹窗对可选模块静默降级（404→隐藏区块） | map 页功能开关可照此模式，避免接口缺失时报错横飞 |
| LLM 双评 + 分级门槛 + 申诉 + 人工改判 | AI 推荐内容需可信度背书时的现成流程参考 |
| 学生投稿"查询码查进度 + 限流 + 审核队列" | 校园 UGC 扩展（活动/失物/二手）可直接套用 |

## 它的弱项（yeu 的相对强项）

无 TypeScript/类型检查、无组件化框架、接口无统一鉴权框架、并发只靠进程内限流（多进程部署会失效）、README 自述"接口无登录权限控制，仅限可信网络"。
