# 仰恩计算机协会官网 · 建站方案

## 0. 一句话

Astro 静态站，8 个栏目，本机构建出制品、服务器只解包切换；内容全是 Markdown，加一篇动态只要新建一个 md 文件。

---

## 1. 技术选型

| 候选 | 判定 | 理由 |
|---|---|---|
| **Astro 5（选定）** | 采用 | 产物是纯 HTML/CSS，零前端运行时；内容集合（Markdown）就是 CMS；本机 16 核构建秒级 |
| Hexo | 备选 | net9 在用，生态成熟；但主题定制要改 EJS/Pug，学生上手比 Astro 组件难 |
| Hugo | 备选 | 构建最快、单二进制；Go template 语法对大一不友好 |
| WordPress | 排除 | 违反「生产机禁止构建/常驻」纪律，插件链无人维护 |
| Next.js / Nuxt | 排除 | 默认要 Node 常驻或 serverless，为一个社团站不值得 |

定这套的硬理由不是偏好，是 `~/.agents/AGENTS.md` 的部署纪律：生产机 `124.221.145.182` 只有 4 核 / 3.6G，同机 50+ 站点，根盘 40G 用了 82%，**禁止在那台机器上构建**。静态产物正好能套进「本机出制品 → 服务器解包切换」这条现成链路。

环境已经验过：node v26.13.0、pnpm 10.28.1、16 核 / 15.2G。

## 2. 信息架构

```
/            首页         hero + 统计 + 最新动态 + 我们做什么 + 近期活动 + 项目墙 + 加入 CTA
/news/       动态         列表（日期 · 部门 · 标签）+ 标签聚合 + 按月归档 + 详情页
/activities/ 活动         卡片带分类筛选（培训 / 比赛 / 分享会 / 团建）
/projects/   项目         卡片 = 技术栈标签 + GitHub + 在线 Demo
/resources/  资源         学习路线、工具、往期讲义
/members/    成员         当届名录（按部门分组）+ 往届归档
/about/      关于         定位、宗旨、做什么、易变信息核对清单
/join/       加入我们     表单 + 隐私说明 + FAQ
/archive/    档案         历史沿革时间线
```

导航 7 项 + 右侧 CTA「加入我们」。**不超过这个数量**——每多一个栏目就多一份要维护的空页面。

## 3. 内容模型（Astro content collections）

```ts
// src/content/config.ts
news:       { title, date, dept, tags[], summary, draft? }        → markdown 正文
activities: { title, date, kind, place?, summary, material? }     → markdown 正文
projects:   { title, owner, stack[], repo?, demo?, year, summary }→ markdown 正文
resources:  { title, kind, level, link, summary }
```

写一篇动态的全部操作：

```bash
# 1. 新建 src/content/news/2026-11-20-first-meetup.md
# 2. 填 frontmatter（title/date/dept/tags/summary）
# 3. 写正文，提交
# 4. 本机构建 → 上传制品 → 服务器切换
```

不需要数据库、不需要登录后台、不需要记密码。这是「学生能接手」的关键。

## 4. 设计系统（仰恩版）

结构照搬 jxauac，色相换成仰恩的红：

```
--bg:#f7f5f2        暖纸白（点阵网格 + 右上角红色光晕）
--surface:#ffffff
--ink:#1a1614       墨
--muted:#6b6259
--accent:#a8121e    仰恩红（主色）
--accent-deep:#7d0d16
--accent-soft:#fbe9ea
--accent-glow:#a8121e14
--border:#e6e1d9
--term-bg:#1c1512   终端卡底色（暖黑，不是纯黑）
--term-ink:#f0dfd2
--radius:14px / --radius-sm:10px
--max:960px         内容最大宽度，比 1200 更适合阅读型站点
```

字体：`system-ui` + `PingFang SC` / `Hiragino Sans GB` / `Microsoft YaHei`；等宽用 `Cascadia Code` / `JetBrains Mono` / `Consolas`。**不引入 Web 字体**——中文字体动辄几 MB，社团站的流量不值得。

首屏右半是仿终端卡，三行打字：`whoami` → 协会名；`cat mission.txt` → 使命；`./join --you` → `[ok] 零基础欢迎`。纯 CSS + 20 行 JS，`prefers-reduced-motion` 下直接全显。

## 5. 加入我们：把隐私写在功能前面

照抄 jxauac 的四条设计，这是四个站里最成熟的一块：

1. **表单不走原生 action**。原生 `<form action>` 会把字段塞进 URL（`?联系方式=xxx`），浏览器历史、代理日志、分享链接全都会带上。改成 `fetch` 提交，无 JS 时按钮禁用并在界面上写明原因。
2. **隐私说明四段**：用途限定 / 报名信息不进公开页面 / 只填一种联系方式 / 记录 IP 摘要属伪名化（说明它不是匿名）。
3. **诚实标注没做到的**：「本站尚未公布统一回复时限与保存期限，如对此有顾虑可暂不提交」。比编一句承诺可信。
4. **表单后接 5 条 FAQ**，拦住重复咨询。

后端落地方式见 §7。

## 6. 部署链路（复用 yeu 现成纪律）

```
本机  bash scripts/build-artifact.sh        # pnpm build → 打包 tar.zst，约 105 秒
服务器 bash /data/yeuca-build/deploy-incoming.sh   # 校验 → 备份 → 冒烟 → 原子切换，35–90 秒
```

沿用既有约定：

- **生产机只解包，不构建**。
- 部署串行化：`server-side-deploy.sh` 里用 `flock`，同一时刻只允许一个部署。
- 低配机构建有硬守卫：低于 8 核 / 8G 直接抛错，云端 CI 用 `ALLOW_LOW_SPEC_BUILD=1` 放行（社团站由本机 16 核构建，正常不会触发）。
- 站点切换用软链（`current → releases/<sha>`），回滚就是改软链。

nginx 侧只加一个 `server` 块，`root` 指向 `current`，静态文件、`try_files $uri $uri/ $uri.html =404`，加 `immutable` 长缓存给 `/_astro/`。
