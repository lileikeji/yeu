## 一、结论先行

**没有可以直接拿来用的「高校计算机协会官网」开源项目。** 这个赛道在 GitHub 上最高 48 星，全是各校自己的一次性作品，没有产品化的模板。

所以正确的做法不是「找一个项目来改」，而是：

1. **骨架自己写**（已经写了，见 `site/`）——因为需求只有 8 个页面，比适配别人的项目便宜；
2. **挑零件插进来**——搜索用 Pagefind，统计先不上，表单复用已有后端；
3. **主题库只当参考实现读**，不 `git clone`。

**不套用任何主题的四条硬理由**

1. **依赖税**。前六名里五个绑 Tailwind（astrowind、astro-paper、astroship、Mizuki 的变体、astro-micro 也用了）。引入 Tailwind 意味着多一层构建、多一个 200 KB+ 的 CSS 产物，而我们全站 CSS 现在是 22 KB 手写。
2. **内容模型错配**。所有主题都是「文章 + 标签 + 归档」的博客模型。我们要的是 news / activities / projects / resources / members 五类异构内容，members 还需要专业和年级两个筛选维度——主题里没有这个概念，改起来比写新的贵。
3. **部署纪律**。AGENTS.md 规定生产机禁止构建，本机出制品。主题带的 Node 依赖链越长，本机构建越慢、制品越大，回滚越笨。
4. **许可**。astroship 是 GPL-3.0，fluid 是 GPL-3.0。套上去以后衍生作品要开源，社团交接时说不清楚。

**但如果一定要挑一个当参考实现读**：

- 学**结构**看 `markhorn-dev/astro-nano`（MIT，956★，几乎零依赖，一个 layout 一个页面，半小时能读完）
- 学**暗色模式怎么写不闪**看 `chrismwilliams/astro-theme-cactus`（MIT，1,752★）
- 学**极简到什么程度还能用**看 `yihui/hugo-xmin`（MIT，981★，全站 HTML+CSS 一共约 140 行）

## 四、表单后端：这条路是空的

搜 `static site form submission backend`、`formspree alternative self hosted`、`cloudflare worker form handler` 三组，最高 4 星：

| 仓库 | ★ | 许可 | 说明 |
|---|---|---|---|
| kevingeary/etch-forms | 4 | MIT | Cloudflare Workers 上的表单处理器 |
| Luckyyaduvanshiofficial/getforms | 3 | Apache-2.0 | 表单转邮件服务 |
| submitsnap/submitsnap-core | 1 | Apache-2.0 | Rust + Axum + PostgreSQL |
| Trel725/formodoro | 1 | MIT | Python，极简表单存储 |
| H190K/email-sending-worker | 1 | MIT | CF Worker + Turnstile + 邮件 |
| wayancc/wyn-forms | 0 | AGPL-3.0 | PHP，自称 Formspree 替代 |

**结论：没有成熟的自托管表单后端。** 全是个人项目、零测试、无维护承诺。往上面押一个每年换人的社团报名入口，等于给自己埋维护债。

**一个反直觉的实测**：`jxauac.cn/join/` 看着像纯静态站，实际抓到的表单是 `<form method="post" action="/api/signups">` + `fetch(\`${BASE}api/signups\`)`——**它自带一个小后端**。说明纯静态站要做报名，必须外挂一个收数据的端点，没有例外。

**三条现实路径，按推荐顺序**

| 方案 | 免费额度（官方页原文） | 接入方式 | 国内可访问 | 判断 |
|---|---|---|---|---|
| **Web3Forms** | **250 次/月，永久免费** | `<form action="https://api.web3forms.com/submit">` + `access_key` | CF 线路，一般可开 | **首选**，纳新季够用 |
| 复用 yeu 主站纳新 API | 无（自己的服务） | 前端 `fetch` 到 `server/api/public/recruit/[slug].post.ts` | 取决于部署 | 与 yeu 同主体时的正解；限流 5 次/小时/IP、管理端审核、docx 导出都是现成的 |
| 自写 Cloudflare Worker + D1 | D1 免费：读 500 万行/日、写 10 万行/日、5 GB 存储 | 约 30–60 行 Worker 收 POST → INSERT | `workers.dev` 不稳，绑自有域名稍好 | 要数据完全自控时选它 |
| Formspree | **Free 仅 50 次/月**，面板只留 30 天 | POST 到其 endpoint | 一般 | **不用**——纳新一天就爆 |
| Supabase | 500 MB DB、无限 API 请求、5 万 MAU | PostgREST 直插 | `supabase.co` 常被干扰 | 闲置 1 周自动暂停，是硬伤 |
| 腾讯问卷 / 飞书多维表格 | 免费版存在，**具体额度未从官方页取到（页面为脚本渲染），标待核** | 建问卷/表单视图 → 链接或 iframe | 好 | 兜底按钮，微信里能填 |

**推荐落法**：`join/` 页现在留的 `[FORM_ENDPOINT]` 直接填 Web3Forms 的 endpoint + 隐藏字段 `access_key`，同时页面放一个「表单打不开就点这里」的腾讯问卷按钮。零后端、零运维、不增加备案负担（表单提交到第三方域名不影响 ICP）。

**不推荐**：上面那六个自托管项目中的任何一个。

## 七、不要做的事（每条都有上面数据支撑）

- 不要找「社团官网模板」——最高 48 星，没有产品。
- 不要套 Tailwind 系主题——多一层构建，CSS 从 22 KB 涨到 200 KB+。
- 不要用 GPL 主题（astroship / fluid）——衍生作品要开源，交接扯不清。
- 不要押表四里任何一个自托管表单后端——全是 0–4 星个人项目。
- 不要为了统计多跑一个 PostgreSQL——3.6G 内存的机器上不划算。
- 不要用 Hexo / Nextra / Nuxt Content / Payload / Strapi / Directus 做主站——它们要么把构建搬回 Node（等于违反「生产机禁止构建」），要么要常驻进程 + 数据库。同机 50+ 站点、3.6 G 内存、根盘 82%，扛不住；学生维护者一次升级就是全站 502。

当前站点是自建的（零主题、零 Tailwind、22 KB CSS、12 页 900 ms 构建）。如果哪天决定改用成熟骨架，按这个顺序：

| 路线 | 骨架 | ★ | 许可 | 能覆盖的栏目 | 人日 |
|---|---|---|---|---|---|
| A | `arthelokyo/astrowind`（原 `onwidget/astrowind` 已 301 迁移） | 6,139 | MIT | 首/闻/活/项/关（4–5 / 8） | 5–7 |
| B | `HugoBlox/kit`（原 wowchemy） | 约 9,800 | MIT | 首/闻/员/项/资（6 / 8） | 4–6 |
| C | `hugo-fixit/FixIt` 或 `HEIGE-PCloud/DoIt` | 1,100 / 941 | MIT | 闻/资/关 | 5–7 |

- **A（AstroWind）**：hero + stats + contact 现成，但绑 Tailwind 4。要新建 news/activities/projects/members 四个 collection，中文 i18n 补一份字典。
- **B（Hugo Blox kit）**：栏目覆盖最全，单二进制、1–3 秒构建，**没人写前端时最省事**；代价是 Hugo 模板语法要重学。
- **C（FixIt / DoIt）**：中文化最好，但本质是博客主题，活动和项目要自己造。

**只当需求清单读的仓库**：`JinkunTian/CAGarden`（★14，PHP + MySQL，无 LICENSE）。功能最贴计协实际需求——纳新报名、OA、物资管理都有，但架构（动态 PHP 站）与静态站纪律相反。读它的**字段和流程**，不读代码。
